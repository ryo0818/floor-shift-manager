# フロアシフト — React フロントエンド

React + TypeScript + Viteで実装した、フロア別シフト管理のフロントエンドです。管理者ログイン、希望シフトの管理・調整・一括確定、提出状況と締切の管理、従業員・フロア管理、スマートフォン向けの希望シフト提出を含みます。

## まず動かす

Node.js 22.13.0以上、npmを使用します。

```bash
npm ci
npm run dev
```

http://localhost:5173 を開きます。開発時はデモモードのため、Spring Bootがなくても画面を操作できます。

- 管理者：`admin` / `demo1234`（「デモ管理者でログイン」でも可）
- 従業員：ログイン画面の「従業員画面を試す」で架空の従業員を選択
- 管理者は現在の半月、従業員は次の半月で開始
- 現在の半月は受付終了、次の半月は受付中のサンプル
- 5フロア・50名の架空データ
- 「田中 葵」には複数フロアと重複する希望があり、警告・一括確定の確認に使用可能
- 「佐藤 葵」などは1フロア固定

**デモデータはメモリ内だけに保存します。ページ内のログアウト・再ログインでは残りますが、ページを再読み込みすると初期化されます。デモのID・パスワードや従業員切り替えは、本人確認やアクセス保護にはなりません。実データは入力しないでください。**

## 実装した機能

### 管理者

- ID・パスワード入力とログアウト
- 半月単位の期間移動、フロア・従業員名・状態で絞り込み
- 一覧／半月表／日別タイムラインの切り替え
- 日別タイムライン：フロアごとの勤務人数、15分単位の人数、従業員別の勤務時間を横棒で表示
- 横棒をクリックして時間・フロアを調整、個別確定、見送り、未確定に戻す
- 表示日・フロア・絞り込み対象の未確定をまとめて確定
- 人数は確定／未確定で分け、区分内で同じ人を重複カウントしない。見送りは人数から除外
- 人数集計は検索・状態絞り込みに影響されない。横棒は絞り込み対象を表示
- シフト追加・編集・削除（管理者は全フロアを選択可）
- 未確定／確定済み／見送りを色とラベルで表示
- 個別確定・選択分の一括確定・表示中の未確定分の全選択
- 確定の重複検出（一括処理は1件でも重複があれば全件中止）
- 確定済み・見送りから未確定に戻す操作
- 提出状況、全日休み希望、提出全体のメモの確認
- 半月ごとの提出締切設定（日本時間）
- フロア名・色の登録と編集
- 従業員登録・編集と複数フロアの割り当て

### 従業員

- スマートフォン中心の半月分の日別入力
- 15分単位、同日に複数の時間帯・フロアを登録
- 割り当てが1フロアなら選択不可、複数ならその範囲で選択
- 希望時間の重複は警告・確認後に許可
- シフトごと、提出全体の任意メモ
- 下書き保存、提出、締切前の修正と再提出
- 全日空欄でも全日休み希望として提出可能
- 締切後は閲覧のみ
- 確定した勤務予定の閲覧機能はなし（本人の提出した希望だけ表示）

## 保留要件と仮仕様

これらは要件決定を意味しません。実装を試せるように一時的に以下を採用しています。

| 未定事項 | 仮仕様 |
| --- | --- |
| 従業員の認証 | デモのみ従業員切り替え。本番はSpring Bootの認証済みセッションがemployeeIdを返す契約 |
| 締切前の確定 | デモでは禁止。APIモードはサーバーのpolicy.allowEarlyConfirmに従う |
| 再提出途中の内容 | 下書きと提出内容を分け、管理者には最後の提出内容を表示 |
| 元の希望履歴 | 最新の提出内容と、管理者による調整前の各シフトを保持。完全な監査履歴はなし |
| フロア未割り当て | 希望行の追加不可（全日休みの提出は可能） |
| メモ文字数 | 1シフト500文字、提出全体1000文字 |
| 配色 | 未確定＝オレンジ、確定＝グリーン、見送り＝グレー |
| 締切未設定期間 | 従業員の受付を停止。管理者が締切を設定して受付開始 |
| 締切の延長・受付再開 | デモでは確定・見送り済みがあれば拒否。全件を未確定へ戻してから再開 |

再提出時に管理者が確定・見送り済みのデータを上書きしないよう、デモでは再提出を拒否します。締切前の確定を採用する際は、再提出との整合性を別途決定してください。

要件原文：`docs/requirements.md`

## Spring Bootに接続する

Java側はこのZIPに含めていません。`docs/API.md` の契約でサーバーを実装してください。

`.env.example` を `.env.development.local` にコピーします。

```dotenv
VITE_DEMO_MODE=false
API_PROXY_TARGET=http://localhost:8080
```

開発サーバーを再起動します。

```bash
npm run dev
```

`/api` への通信がSpring Bootに転送されます。本番ビルドは既定でデモ無効です。ブラウザのセッションCookieとCSRFトークンを使用する想定で、初回は `GET /api/session` を呼びます。認証・権限・締切・重複・一括確定のトランザクションは必ずサーバー側にも実装してください。

従業員認証の具体的な画面・方式は未定のため本番の従業員ログイン画面は実装していません。サーバーで認証したセッションが `role: "employee"` と本人のemployeeIdを返すと、本人の画面に入ります。

## コマンド

```bash
npm run test       # 入力制約・権限・状態遷移・一括確定などのテスト
npm run build      # 型チェック＋本番ビルド（デモ無効）
npm run build:demo # 型チェック＋操作確認用デモビルド
npm run preview    # 最後にビルドしたdistを確認
```

`npm run preview` はAPIへの開発用プロキシを提供しません。APIなしでビルド結果を確認する場合は、先に `npm run build:demo` を実行してください。
