# フロア別シフト管理システム 要件定義（たたき台）

## 1. 概要

アルバイト従業員の希望シフトを収集し、管理者がフロア別に確認・調整・確定するシステム。

従業員が登録した希望シフトを、そのまま確定できるようにし、管理者による打ち直しを不要とする。

| 項目 | 内容 |
|---|---|
| フロントエンド | React |
| バックエンド | Java／Spring Boot |
| 想定フロア数 | 5フロア |
| 想定従業員数 | 1フロア約10人、全体約50人 |
| 管理者の利用端末 | PC中心 |
| 従業員の利用端末 | スマートフォン中心 |
| デザイン | 作成済みの画面構成をベースとする |

※複数フロアを兼務する従業員がいる場合、実人数は約50人より少なくなる想定。

## 2. 利用者・権限

| 機能 | 管理者 | 従業員 |
|---|---|---|
| フロア・従業員の管理 | 可能 | 不可 |
| 従業員へのフロア割り当て | 可能 | 不可 |
| 提出締切の設定 | 可能 | 不可 |
| 希望シフトの登録・修正・削除 | 全員分 | 自分の分のみ・締切前 |
| 希望シフトの提出・再提出 | — | 自分の分 |
| 提出状況・提出された希望の確認 | 全員分 | 自分の分 |
| シフトの確定・見送り・未確定への差し戻し | 可能 | 不可 |
| 確定シフトの閲覧 | 全員分 | 今回は対象外 |

### 管理者の認証

- 管理者アカウントは1つとする。
- ログインID＋パスワードで認証する。
- 全従業員・全フロアを管理できる。
- 複数の管理者アカウントや、管理者間の権限分けは今回の対象外とする。

### 従業員の認証

- ログイン方式・アクセス方法は未定とする。
- 自分の希望シフトを識別・操作できる仕組みは必要とする。

## 3. フロア・従業員管理

管理者は、フロアと従業員を登録・編集し、従業員ごとに勤務可能なフロアを割り当てる。

| 条件 | 希望シフト登録時の動作 |
|---|---|
| 割り当てフロアが1つ | 自動設定し、従業員は変更不可 |
| 割り当てフロアが複数 | 割り当て済みフロアから従業員が選択 |
| 管理者による登録・調整 | 割り当て外を含む全フロアから選択可能 |

## 4. 希望シフトの入力

### 入力項目

| 項目 | 内容 |
|---|---|
| 勤務希望日 | 対象期間内の日付 |
| 開始時刻 | 15分単位 |
| 終了時刻 | 15分単位 |
| 希望フロア | 従業員に割り当てられたフロア |
| シフトごとのメモ | 任意入力 |
| 半月分の提出全体のメモ | 任意入力 |

### 入力ルール

- 同じ日に複数の時間帯・フロアを登録できる。
- 日付をまたぐ勤務は対象外とする。
- 終了時刻は開始時刻より後とする。
- 休憩時間は入力・管理しない。
- 時間集計は「終了時刻 − 開始時刻」のシフト時間とする。
- 提出内容に入力がない日は、休み希望として扱う。

### 時間が重なる場合

希望シフトでは、同じ従業員の時間重複を許可する。ただし、同じフロア・別フロアを問わず警告を表示し、確認後に登録できるようにする。

例：

> 登録済みの希望シフトと時間が重複しています。このまま登録しますか？

前のシフトの終了時刻と、次の開始時刻が同じ場合は重複としない。

## 5. 提出期間・締切

### 提出単位

| 区分 | 対象期間 |
|---|---|
| 前半 | 毎月1日〜15日 |
| 後半 | 毎月16日〜末日 |

### 締切の設定

- 管理者が対象期間ごとに提出締切の日付・時刻を設定する。
- 従業員画面に対象期間と締切を表示する。
- 締切後の希望シフトの追加・修正・削除は管理者のみ可能とする。

## 6. 下書き・提出・再提出

- 入力途中の内容を下書き保存できる。
- 「希望シフトを提出する」ボタンで、半月分をまとめて提出する。
- 管理者は従業員ごとの未提出・提出済みを確認できる。
- 提出後も、締切前なら従業員が修正・再提出できる。
- 締切後は従業員による変更・再提出を不可とする。

| 状態 | 意味 |
|---|---|
| 未提出 | 対象期間の希望をまだ提出していない |
| 提出済み・一部の日が空欄 | 空欄の日は休み希望 |
| 提出済み・全日空欄 | 対象期間の全日が休み希望 |

## 7. 管理者による調整・確定

- 管理者は提出された希望シフトとメモを確認する。
- 必要に応じて日時・フロアを調整する。
- 希望シフトをそのまま確定できるようにする。
- 確定のために同じ内容を別画面へ打ち直す操作は不要とする。

### シフトのステータス

| ステータス | 意味 |
|---|---|
| 未確定 | 管理者が調整・検討中 |
| 確定済み | 勤務予定として採用 |
| 見送り | 今回は採用しない |

- 状態は色とラベルの両方で表示する。
- 見送りにしても、希望シフトは削除しない。
- 確定した勤務人数・時間の集計には、確定済みのみを含める。

### 状態変更

| 変更前 | 変更後 | 操作者 |
|---|---|---|
| 未確定 | 確定済み | 管理者 |
| 未確定 | 見送り | 管理者 |
| 確定済み | 未確定 | 管理者 |
| 見送り | 未確定 | 管理者 |

確定済みシフトを修正する場合は、一度未確定に戻してから修正・再確定する。確定済みのまま直接変更はできない。

## 8. 個別確定・一括確定

### 操作

- シフトを1件ずつ確定できる。
- チェックした複数のシフトを一括確定できる。
- 表示中の未確定シフトを全選択できる。
- フロア・対象期間で絞り込んで操作できる。

### 重複チェック

確定シフトでは、同じ従業員の勤務時間の重複を禁止する。フロアが異なる場合も対象とする。

一括確定時は、以下の両方を確認する。

- 選択したシフト同士の重複
- 選択したシフトと既存の確定シフトとの重複

### 一括確定で重複がある場合

- 対象全件の確定を中止する。
- 一部だけ確定することはしない。
- 重複する従業員・日時・フロアを表示する。
- 管理者が修正するか、対象を選択から外して再実行する。

## 9. 必要な画面

※以下は画面の機能単位。別ページにするか、タブ・ダイアログでまとめるかは画面設計時に決める。

| 画面 | 主な機能 |
|---|---|
| 管理者ログイン | ID・パスワード認証 |
| 管理者シフト管理 | 希望の確認、調整、個別・一括確定、見送り、状態表示 |
| 提出状況・締切管理 | 半月ごとの締切設定、従業員別の提出状況確認 |
| フロア管理 | フロアの登録・編集 |
| 従業員管理 | 従業員の登録・編集、勤務可能フロアの割り当て |
| 従業員希望シフト登録 | 日時・フロア・メモ入力、下書き保存、提出・再提出 |

## 10. 今回の対象外

- 従業員による確定シフトの閲覧
- 従業員向けの確定シフト公開機能
- 複数の管理者アカウントと権限分け
- 日付をまたぐ勤務
- 休憩時間の管理・休憩を差し引いた実働時間の計算

## 11. 保留・未確定事項

| 項目 | 現状 |
|---|---|
| 従業員のログイン・アクセス方法 | 未定 |
| 提出締切前に管理者が確定できるか | 保留 |
| 再提出前の修正途中の内容 | 管理者には前回提出分を表示する案。未確定 |
| 管理者が調整する前の希望内容 | 元の希望を履歴として残す案。保存方法・範囲は未確定 |
| フロア未割り当ての従業員 | 希望登録不可とする案。未確定 |
| メモの文字数上限 | 未定 |
| ステータスの具体的な配色 | 未定 |
| DB・サーバー・公開環境 | 未定 |

**以前作成したコードは画面のたたき台であり、今回整理した要件に合わせた修正が必要です。** 特に、希望提出・ステータス管理・認証の追加、夜勤・休憩管理の除外が変更点になります。
