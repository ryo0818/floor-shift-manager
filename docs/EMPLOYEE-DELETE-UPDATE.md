# 2026-10-17 従業員削除

管理者の「従業員・フロア」画面で、従業員行の「削除」を押し、確認画面で実行します。

- 未使用の従業員情報と紐づくログインアカウントを削除。ログインセッションも失効し、再ログインできなくなります。
- アカウント未作成の従業員も削除できます。フロア自体は削除しません。
- 過去・未来を含む全期間に、勤務シフト（未確定／確定／見送り）または希望の提出・下書き保存記録がある場合は削除しません。
- 全日休みの提出、空の下書き保存記録も保護対象です。
- 使用中・権限不足・更新競合の場合は、従業員／アカウントを含めて変更しません。
- 削除は復元不可。履歴がある退職者の利用停止（無効化）は今回含みません。

## 反映方法

設定済みの backend/.env と公開用Nginx設定を保持し、frontend/backend を更新してください。
前に案内した停止→再ビルド→起動の手順で、両方のDockerイメージとコンテナを更新します。
今回の従業員削除に追加DDLはありません。10月7日のアカウント機能のカラム追加を未実施なら `python -m app.manage migrate` を実行してください。再実行しても既存データは保持します。
具体的なDocker更新コマンドは [前回の更新手順](FLOOR-DELETE-UPDATE.md) を参照してください。

## API

POST /api/commands に type="deleteEmployee", id="従業員ID" を追加。
period, expectedRevision と既存のCookie・CSRFトークンが必要です。
全期間確認と従業員・アカウント・セッション削除は、書き込みロック下の同一トランザクションで実施します。
