# Pythonバックエンド

全体のセットアップとDB初期化は [ルートのREADME](../README.md) を参照してください。
API仕様は [docs/API.md](../docs/API.md)、DDLは `app/schema.sql` です。

バックエンドのコマンドはこの `backend/` ディレクトリで実行します。
実際のDB接続情報は `.env.example` をコピーした `.env` に設定します。

### 従業員の確定予定と退職状態

- 従業員のワークスペースには `confirmedSchedule` として本人の確定済み勤務だけを返します。管理者メモ・変更履歴・他人の勤務は含みません。割り当て解除後のフロアでも確定勤務の名称を確認できます。
- 管理者の `setEmployeeActive` コマンドで在籍／退職を変更します。退職時は既存セッションを削除し、ログイン・希望提出・新規勤務追加・確定を拒否します。通常の従業員編集では在籍状態を変更しません。
- 退職しても過去・未来のシフト、下書き、提出履歴、アカウントは保持します。管理者が各半月を確認し、不要な確定勤務は未確定に戻して見送りにしてください。在籍に戻すと元のアカウントでログインできます。
- `employees.data` の `active` が未設定の既存従業員は在籍扱いです。DDL変更・データ移行は不要です。frontend/backendを同時に更新してください。
- 変更ありの件数と絞り込みは選択した半月が対象です。取り消し件数は各従業員の直近の変更提出に含まれる件数で、未読数ではありません。
